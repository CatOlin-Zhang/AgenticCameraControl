# xpai-build

> 这个文件夹只放构建工具，**不要拷进分发包**。分发的是 `xpai-camera-control-source` 文件夹。

## 一句话概括

把 `scripts/toolkit/` 下的 `.py` 源码**先混淆敏感常量、再编译成 `.pyd`、最后删掉源码**，让 `xpai-camera-control-source` 就地变成可分发的版本。

## 怎么用

1. 把干净的 `.py` 源码放进 `xpai-camera-control-source/scripts/toolkit/`（其他改动的 `mcp_server.py`、`references` 等也一并覆盖进对应位置）。
2. 双击本目录的 `build.bat`。
3. 成功后，`xpai-camera-control-source` 即为分发版（`toolkit` 全是 `.pyd`，源码与 `config.yaml` 已删）。

## 构建做了什么（5 步）

| 步骤 | 动作 |
|------|------|
| 0. 校准 | 实测本机 `hashlib.scrypt` 基线，自动选定参数使**单次解码 ≈ 60 秒** |
| 1. 混淆 | 敏感字面量逐个打包 + 内联解码表达式 + 敏感常量名随机重命名 + 诱饵注入 |
| 2. 编译 | Cython 编译为 `.pyd`，同时剥离全部 docstring 与函数签名 |
| 3. 验证 | 纯 `.pyd` 状态：导入、模拟攻击（找解码入口/指纹/耗时推算）、关键逻辑回归；二进制扫明文，命中即中止 |
| 4. 清理 | 删除源码、`.c`、`__pycache__`、`config.yaml` |

## 混淆方案（核心）

设计目标：agent 静态破解**全量还原 ≥ 60 分钟**，单次解码尝试即超过主流 agent 框架的工具调用超时（30~300s）。

- **去预言机**：模块属性中不存在任何"解码函数"。解码逻辑以**自包含内联表达式**直接生成在每个使用点，无法通过"枚举模块属性 + 调用"一步全解。
- **单一 bytes 包**：每个秘密打包成一个无结构指纹的 `bytes`（头部参数 + 随机 salt + 乱序密文）。置换由派生密钥确定性重演，不随包存放。
- **时间成本**：解码前经 `hashlib.scrypt` 派生密钥，单次 ≈ 校准值（默认 60 秒）。全包数量（真实+诱饵）≥ 60，全量枚举 ≈ 60+ 分钟。
- **符号去语义**：敏感常量名（端点路径、KEY、UA、报警映射、云端 URL 等）构建期重命名为每构建随机的无意义标识符。
- **诱饵稀释**：注入与真实包结构完全相同的假包（解码后为无语义垃圾），攻击者无法区分真假，必须全付时间成本。
- **合法开销缓解**：进程级解码缓存（藏于 `sys` 随机属性）——同一进程内每个秘密只付一次时间成本，之后全部命中缓存。MCP 服务器为长驻进程，首调逐个解锁后渐进命中。

> 每次打包都先做"解码(编码(x)) == x"往返自检，不一致立即报错、绝不写入源码。

### 校准参数位置（`build_toolkit.py` 顶部）

| 常量 | 含义 | 默认 |
|------|------|------|
| `DECODE_TARGET_SECONDS` | 单次解码目标耗时（秒） | 60 |
| `MIN_ATTACK_TOTAL_MINUTES` | 全量枚举预估下限（分钟），决定包总数下限 | 60 |
| `SCRYPT_N_LOG2_MAX` | scrypt n 指数上限（受 Windows 内存/maxmem 约束） | 20 |

校准时先抬高 `n`（受内存上限），不足的时间差用 `p` 线性补齐；实际选定的 `n`/`p` 写入每个包的头部，运行时据此还原。

### 运行时环境变量

| 变量 | 作用 |
|------|------|
| `XPAI_VERIFY=1` | 快速模式（验证/调试用，scrypt 降到毫秒级）。**不要随分发环境设置** |
| `XPAI_DECODE_N` | 覆盖 scrypt 的 `n=2^X`（调试用，正常勿设） |

### 合法使用的耗时预期

- 每个秘密在进程内**首次**使用时阻塞一次解码（≈ 校准值，默认约 60 秒），之后同进程命中缓存为瞬时。
- 各功能首调渐进解锁；长驻进程跑满一轮后不再有感。
- 若觉得首调太慢，可调低 `DECODE_TARGET_SECONDS`，但请同步确认包总数仍满足 `MIN_ATTACK_TOTAL_MINUTES`（脚本会在验证阶段自动断言）。

## 防出错机制（失败即中止，不产出坏包）

- 编码往返自检、语法 `compile()` 检查、残留明文扫描（去 docstring/注释后），任一失败立即停止。
- 混淆后仍扫到敏感明文 → 中止（不会带洞出货）。
- 纯 `.pyd` 验证含"模拟攻击"：模块属性中找解码函数/明文残留应一无所获；按校准参数推算全量攻击时长必须 ≥ 目标值。
- 编译或导入验证失败 → 中止，源码按提示从备份重新拷入再跑。

## 红线提醒

1. **本文件夹不进分发包**（含混淆逻辑与特征模式）。
2. **改了源码必须重跑**：旧的 `.pyd` 是上次编的，新源码要重新构建覆盖。
3. **真机回归**：脚本能保证"编解码正确、能编译、能导入"，但保证不了真机协议行为——分发前请用真摄像头跑一遍补光/图像/追踪/事件监听。
4. 静态加固防不住"运行时打桩 `requests` 抓包"；如需要，另行评估把发包下沉到 C 层（见计划阶段六，未并入本脚本）。
